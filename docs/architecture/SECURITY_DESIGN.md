# Lila Home — 安全设计（Stage 0-05）

> 文档：`docs/architecture/SECURITY_DESIGN.md`
> 状态：设计（PLANNED，未实施、未部署、未测试）
> 依据：服务器审计、网络架构、开源审计、设备兼容性审计
> 原则：只读审计阶段不改任何安全配置；本文件所有措施均为 Stage 1 待实施项，实施前须逐项批准。

## 1. 安全现状（已实测事实，见 SERVER_AUDIT.md）

| 项目 | 现状 | 含义 |
|---|---|---|
| UFW | inactive | 主机防火墙未启用 |
| iptables INPUT | policy ACCEPT，空规则 | 入站默认放行，靠服务绑定控制暴露面 |
| iptables FORWARD | policy DROP | 转发默认拒绝 |
| 公网监听 | 0.0.0.0:80/443/22/24443/24444 | 22/80/443 为现有业务；24443/24444 属 3x-ui，需用户确认是否为有意暴露 |
| 业务端口 | 其余只绑 127.0.0.1 | 现有部署较好的做法，Lila Home 必须沿用 |
| SSH | ssh.service 在跑，22 公网监听 | 沿用现有 SSH 通道，不另开管理端口 |
| Docker socket | 非 sudo 用户无权访问 | 属实测现象；Lila Home 部署须用有权限的部署身份，不放宽 socket 权限 |
| Tailscale/WireGuard | 未安装 | VPN 待 Stage 1 选型后部署 |
| 时区/NTP | Etc/UTC，NTP 已同步 | 审计日志时间以 UTC 为准，前端再换算显示 |

**本阶段不修改上述任何一项。** 防火墙策略、Swap、时区等变更均须用户单独批准。

## 2. 威胁模型（家庭自用范围）

| 威胁 | 影响 | 缓解（设计） |
|---|---|---|
| 公网扫描/爆破管理端口 | HA/MQTT/数据库被直接攻击 | 管理端口永不暴露公网，只绑回环/VPN；SSH 沿用现有加固 |
| 账号被盗用后控设备 | 非法开关设备、改热水器温度 | 强密码 + 会话管理 + RBAC + 审计日志；热水器等高风险操作须二次确认（Stage 1 定） |
| 厂商云 Token 泄露 | 云账号被冒用 | Token 不进仓库、不进数据库明文、只存本地秘密管理；定期轮换 |
| 家庭 LAN 被侵入 | 设备被局域网内冒充控制 | HA 与设备同 LAN 内仍须配对码/Token；不信任“在 LAN 内即合法” |
| 供应链/依赖漏洞 | 如 Mosquitto CVE-2026-110486 | 选型下限 Mosquitto ≥2.1.3；依赖定期审查 |
| 备份泄露 | 数据库备份含用户信息 | 备份加密、密钥与备份分离、恢复演练 |
| 误操作 | 误删设备/场景、错控热水器 | 软删除、操作留痕、危险操作二次确认、热水器安全联锁不可绕过 |

## 3. 认证与授权

### 3.1 认证

- 登录：邮箱 + 密码（哈希存储，算法 Stage 1 定，Argon2id 优先）。
- 会话：JWT 或安全 Session（二选一，Stage 1 定）；Token 只存 SHA256 哈希；支持吊销与过期。
- 不做：不恢复 QQ 登录、不恢复微信登录（沿用用户既定要求）；不设模拟授权页；不索要用户密码、验证码、私钥。
- 失败处理：登录失败限流；失败记录进审计日志；不泄露“账号不存在还是密码错”。

### 3.2 RBAC（角色权限）

| 角色 | 权限 |
|---|---|
| Owner | 全部权限：用户管理、角色管理、安全设置、审计日志、设备与场景管理 |
| Admin | 设备、房间、场景、集成管理；不可改用户角色、不可改安全设置 |
| Member | 控制已授权的设备、执行场景、查看状态 |
| Viewer | 只读：查看状态与历史，不可控制 |

- 权限校验在统一服务层做，不在前端做（前端只做界面隐藏，不作安全边界）。
- 设备级授权：Member 只能控被授权的设备；未授权设备返回 403。

### 3.3 设备控制权限

- 所有设备操作经统一服务层鉴权 + 审计。
- 路由器：只做只读监控；重启/改配置/限速等高风险控制不在 Stage 0 范围，Stage 1 须另行核实与批准。
- 热水器：只调厂商协议已暴露的功能（目标温度/模式/开关）；**不得绕过原厂安全保护**（超温、燃气、干烧等联锁不在 HA 控制面内）；危险参数在 API 层拒绝。
- 红外设备：只发指令，不谎报执行结果（状态机见 API 设计）。

## 4. 网络安全

- VPS 只暴露 80/443（Nginx）与 22（SSH）；HA（8123）、MQTT（1883）、PostgreSQL（5432）、Redis（6379）一律不暴露公网。
- VPS ↔ 家庭 LAN 只通 VPN 隧道（Tailscale 托管或 Headscale 自托管，待选型）。
- 家庭 LAN 内：HA 与设备通信用配对码/Token；mDNS 发现只在 LAN 内。
- 容器网络隔离：Lila Home 容器与现有业务容器网络隔离；数据卷隔离；不得复用 infra-db-1。
- 出站：API 访问厂商云只走必要的域名与端口；不开放任意出站代理。

## 5. 秘密管理

- **绝不写入仓库**：密码、Token、API Key、配对码、证书、私钥、设备 IP、家庭内网信息。
- **绝不写入数据库明文**：厂商 Token、密码、密钥；只存本地秘密管理的引用名。
- **绝不在聊天中索要**：服务器密码、私钥、验证码、完整 OAuth Token。
- 本地秘密管理：Stage 1 定具体工具（Docker secrets / 环境变量文件 + 权限控制 / Vault 类方案三选一）；`.gitignore` 草案见仓库根目录，含家庭敏感信息路径。
- 轮换：厂商云 Token 泄露或人员变动时须轮换；轮换流程 Stage 1 定。

## 6. 审计日志

- 记录：登录/登出、设备控制、场景执行、用户/角色变更、配置变更、集成启用/停用。
- 字段：用户、动作、对象、脱敏详情、IP、时间（UTC）。
- 审计日志只追加、不修改、不删除；保留周期 Stage 1 定。
- 日志不得含 Token/密码/密钥明文。

## 7. 数据保护与备份

- 备份对象：PostgreSQL 数据卷、HA 配置、VPN/网络密钥、场景与设备元数据。
- 备份要求：加密；密钥与备份分离；异地/离线副本；定期恢复演练（演练前不得宣称恢复能力）。
- 现有业务备份状态未检测（见 SERVER_AUDIT.md 1.3 节），Lila Home 备份须独立设计，不得假设现有备份覆盖 Lila Home。
- 删除：用户数据删除走软删除 + 审计；备份中的过期数据按保留周期清理。

## 8. 开源合规安全

- 选型下限：Mosquitto ≥2.1.3（CVE-2026-110486）；Tailscale ≥v1.104.4（含 TS-2026-014 至 -017 修复）或对应 Headscale v0.29.7。
- GPL-3.0 成分（ESPHome C++ 运行时、Zigbee2MQTT）：家庭自用不分发不触发源码提供义务；后续开放源码须重新审查。
- 依赖审查：Stage 1 建立依赖清单与许可证复核流程；`THIRD_PARTY_NOTICES.md` 随选型更新。

## 9. 安全测试要求（Stage 1 执行，见测试规划摘要）

- 权限测试：越权访问、未授权设备控制、Viewer 控制尝试。
- 注入与校验测试：危险参数拒绝、SQL 注入、XSS。
- 会话测试：过期、吊销、重放。
- 端口扫描复核：部署后重新 `ss` 核查，确认管理端口未暴露公网。
- 断网/VPS 故障演练各一次并记录。
